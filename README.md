# 内网设备管理平台（LAN Device Manager）

企业/家庭内网设备的可视化管理平台：自动采集企业路由器的实时流量与 DHCP 设备清单，
提供设备台账、行为管控、流量统计、消息下发等能力，替代路由器自带的简陋 IP 流量查询。

支持 TL-R483G 等 TP-Link 企业路由器（页面登录抓取），也适用于其他支持网页登录的设备。

## 功能特性

- **设备台账**：自动发现内网设备（IP / MAC / 主机名 / 类型推断），支持批量标注使用人
- **在线状态**：采集器 ICMP + 服务端 TCP 并发探测双兜底，真实反映设备上下线
- **实时/统计视图**：实时带宽 Top 榜、历史流量统计（日 / 周 / 月 / 全部）
- **行为管控**：限速规则、应用限制、时段策略（工作时间 / 休息 / 假期）的统一管理入口
- **消息下发**：平台向指定 PC 群发通知（每台 PC 运行一个轻量接收端脚本弹窗）
- **用户管理**：多账号登录，管理员 / 普通用户角色；路由器凭据保存在平台内维护
- **抓取总开关**：一键停止一切抓取（采集 + 探测）；一键重置清空数据重新开始
- **可视化仪表盘**：实时速率、活跃设备、流量排行图表，自动刷新

## 架构

```
┌────────────┐  采集(Playwright)   ┌────────────┐   REST API    ┌────────────┐
│ 企业路由器  │ ◄────────────────  │ 采集器容器  │ ───────────►  │  后端服务    │
│ TL-R483G   │  (lan-collector)   │ (collector) │  snapshot     │ (lan-backend)│
└────────────┘                    └────────────┘               └─────┬──────┘
        ▲  ICMP/TCP 探测（NAS 常驻兜底）                            │
        └───────────────────────────────────────────────────────────┘
                                        ┌────────────┐
                                        │  Web 前端   │  nginx :8088
                                        │ (React+Vite)│
                                        └────────────┘
```

- `web/`：React + Vite + TypeScript 前端（浏览器访问入口，nginx 托管）
- `server/`：Express 后端（REST API + JSON 文件存储，node:20 容器）
- `collector/`：采集器（python + Playwright，定时登录路由器抓 ip-stat / DHCP 清单推送后端）
- `server-data/`：运行时数据（db.json 等，由 volume 持久化，不入库）

## 快速开始（Docker Compose 一键部署）

前置：一台 Linux 主机/NAS（x86_64，支持 Docker Compose）、企业路由器管理页面可访问。

### 1. 准备配置

```bash
git clone <本仓库地址> && cd lan-dm
cp .env.example .env
```

编辑 `.env`：

```ini
# 平台对外端口
WEB_PORT=8088
# 后端数据目录（宿主机持久化路径）
DATA_DIR=/path/to/server-data
# 路由器管理地址 / 账号 / 密码（采集器登录用）
ROUTER_URL=http://192.168.102.1
ROUTER_USER=admin
ROUTER_PASS=你的路由器密码
# 采集密钥（后端与采集器之间的鉴权，自定一串随机字符）
COLLECTOR_KEY=请改成一串随机字符
# 采集间隔（秒，默认 600 = 10 分钟）
COLLECTOR_INTERVAL=600
# 需要豁免恒在线的设备 IP（如平台自身所在 NAS 的 IP，可留空）
NAS_IP=
```

### 2. 构建前端

```bash
cd web
npm install
npm run build
# 构建产物输出到 dist/output + dist/output_resource，复制到 ../dist 目录
```

### 3. 启动

```bash
docker compose up -d --build
```

浏览器访问 `http://<服务器IP>:${WEB_PORT}/`，首次进入创建管理员账号。

### 4. 消息接收端（可选）

每台需要接收平台通知的 Windows PC，双击运行 `client/安装消息接收端.bat`，脚本注册开机自启并
每 15 秒轮询平台消息，收到后本机弹窗提示。首次使用需在 `client/内网消息接收端.ps1` 参数中
填写平台地址 `-Server http://<平台IP>:8088` 与采集密钥 `-Key <COLLECTOR_KEY>`。

## 配置说明（环境变量）

| 变量 | 说明 | 默认 |
|---|---|---|
| WEB_PORT | 平台对外端口 | 8088 |
| DATA_DIR | 后端数据持久化目录（挂载到容器 /data） | ./server-data |
| ROUTER_URL | 路由器管理页地址 | http://192.168.102.1 |
| ROUTER_USER / ROUTER_PASS | 路由器登录凭据 | 必填 |
| COLLECTOR_KEY | 采集器与后端通信密钥 | 必填 |
| COLLECTOR_INTERVAL | 采集周期（秒） | 600 |
| COLLECTOR_POLL | 即时抓取轮询间隔（秒） | 5 |
| NAS_IP | 豁免恒在线的设备 IP（可空） | 空 |
| PORT | 后端容器内监听端口 | 3001 |

## 与路由器联动说明

- 平台本身**不修改**路由器配置：只登录读取「IP 流量统计」「DHCP 客户端列表」页面数据；
- 限速 / 应用限制 / 时段策略：平台提供统一配置与下发接口，按你的路由器型号接入执行通道
  （演示环境默认展示平台内的策略配置，具体执行需对接路由器行为管控接口）。

## 常见问题

- **点击刷新没反应？** 平台刷新是通知 NAS 采集器立即抓取一次路由器，约 10~40 秒内更新；
- **设备显示离线/在线不准？** 在线状态采用 采集器 ICMP + 服务端 TCP 探测 双兜底，
  内网设备关机后约 1~2 分钟内会正确标记；
- **抓取总开关**：停止后所有采集与探测暂停，页面数据冻结在暂停前状态。
